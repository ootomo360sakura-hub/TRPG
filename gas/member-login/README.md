# 会員ログインゲート(GASウェブアプリ)

Googleサイトに埋め込める、ID+パスワード式のログインページ。
`docs/google-sites-member-pages.md` の「方法2」を発展させた実装で、
共通パスワードではなく **会員ごとに個別のID/パスワード** を発行できる。

## 構成

| ファイル | 役割 |
|----------|------|
| `Code.gs` | サーバー側ロジック(認証・会員管理・セッション) |
| `login.html` | ログインフォーム(ウェブアプリの画面) |
| `member.html` | ログイン成功後に表示される会員コンテンツ(**要編集**) |
| `appsscript.json` | マニフェスト(タイムゾーン・ウェブアプリ設定) |

## 仕様

- 会員名簿は専用のGoogleスプレッドシートで管理(`setup()` が自動作成)
- パスワードは平文保存せず、会員ごとのソルト付き **SHA-256ハッシュ** で保存
- ログイン成功でセッショントークンを発行(有効期限 **6時間**、`CacheService` 管理)
- 会員コンテンツはトークン検証を通ったときだけサーバーから返す
  (=ページのHTMLソースを見ても会員コンテンツは含まれていない)
- 同一IDで **5回** ログインに失敗すると **10分間** ロック(総当たり対策)
- タブを閉じるまでは再ログイン不要(`sessionStorage` でトークン保持)

## セットアップ手順

### 1. GASプロジェクトを作る

1. [script.google.com](https://script.google.com) →「新しいプロジェクト」
2. このフォルダの4ファイルを作成して内容を貼り付ける
   - `Code.gs` → 既存の「コード.gs」に貼り付け
   - `login.html` / `member.html` →「ファイルを追加 → HTML」で作成して貼り付け
   - `appsscript.json` → エディタ左の「プロジェクトの設定」で
     「appsscript.json マニフェストをエディタで表示する」をONにして貼り付け

(ローカルから直接反映したい場合は [clasp](https://github.com/google/clasp) で
`clasp push` してもよい。このフォルダがそのままpush対象になる構成)

### 2. 初期化と会員登録(エディタから実行)

1. 関数の選択で **`setup`** を選んで実行 → 初回は権限の承認画面が出るので許可する。
   実行ログに会員名簿スプレッドシートのURLが出る
2. `sample_addMember` の中身を書き換えて実行し、会員を登録する:

   ```javascript
   function sample_addMember() {
     addMember('taro', 'taro-no-pass-123', '太郎');   // (ID, パスワード, 表示名)
   }
   ```

   - パスワードは8文字以上
   - 退会処理は `removeMember('taro')` を同様に実行
   - 名簿スプレッドシートにはハッシュしか入らないので、
     発行したパスワードは登録時に本人へ直接伝えること(あとから確認はできない)

### 3. 会員コンテンツを編集

`member.html` のリンク一覧を実際のURL(会員向けサイト・予定表・ドライブ等)に書き換える。

### 4. ウェブアプリとしてデプロイ

1. 右上 **「デプロイ」→「新しいデプロイ」→ 種類「ウェブアプリ」**
2. 設定:
   - 次のユーザーとして実行: **自分**
   - アクセスできるユーザー: **全員**
3. デプロイして発行された `https://script.google.com/macros/s/…/exec` のURLをコピー

コードを修正したら「デプロイを管理 → 編集 → 新バージョン」で反映する
(新しいデプロイを作るとURLが変わってしまうので注意)。

### 5. Googleサイトに埋め込む

1. Googleサイトの入口ページで **「挿入」→「埋め込む」→「URL」** にデプロイURLを貼る
2. 埋め込みサイズを十分な高さ(500px程度)に調整する

ウェブアプリのURLを直接会員に共有して、サイトに埋め込まず単独で使うこともできる。

## セキュリティ上の注意(必読)

これは**趣味サークル向けの簡易実装**であり、商用レベルの認証基盤ではない。

- `member.html` に直接書いた内容とリンクURLは、ログインした会員全員に見える。
  **リンク先(GoogleサイトやドライブのURL)は会員経由で漏れうる**前提で、
  リンク先自体も「リンクを知っている全員」ではなくGoogleアカウント制限を
  かけられるものは、かけておくのが望ましい(二段構え)
- 退会者が出たら `removeMember()` に加え、必要ならリンク先URLの変更も検討する
- 個人情報・決済情報など、漏れたら実害があるものはこの仕組みで守らないこと
- 本格的な要件になったら Firebase Authentication 等への移行を推奨
  (`docs/google-sites-member-pages.md` の方法3)
