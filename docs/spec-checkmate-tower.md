## 1. コンセプト

> **負けたら100%自分の読みミス。運は一切介在しない。**

小さな盤面で、敵の次の一手がすべて見えている状態から最善手を探す戦術パズル。
プレイヤーは「敵を倒す」よりも「敵の攻撃を空振りさせる」ことで盤面を制圧する。

### 1.1 コアループ

```
階層マップで進路を選ぶ
   ↓
戦闘(1マップ・2〜6ターンで決着)
   ↓
報酬でスキル/装備を1つ獲得
   ↓
次の階層へ(全10〜15階層で塔を踏破)
```

### 1.2 参考タイトル

| タイトル | 参考にする点 | 変える点 |
|---------|------------|---------|
| Into the Breach | 敵行動の完全予告、押し出し中心の戦術、小さな盤面 | ランダム生成をやめ、全ステージ手作りの詰将棋にする |
| Final Fantasy Tactics | クラスとスキルによる成長 | 乱数(命中率・回避)を全廃 |
| 詰将棋・パズルゲーム | 「解がある盤面」としての設計 | RPGの成長と物語を載せる |

## 2. 設計原則

この5つは実装中に迷ったときの判断基準とする。**原則同士が衝突した場合は番号が小さいほうを優先する。**

### 原則1. 乱数を一切使わない

- 命中率なし(攻撃は必ず当たる)
- ダメージ幅なし(固定値)
- 会心・状態異常の確率なし
- 敵の行動選択も決定的(同じ盤面なら必ず同じ行動)
- ステージ生成もランダムでない(全て手作り)

**理由**: 負けの原因が常にプレイヤーの判断に帰属する。上達実感が最大化される。
副次的に、バランス調整とデバッグのコストが桁違いに下がる(少人数開発では決定的に重要)。

### 原則2. 脅威は必ず事前に見える

そのターン中にプレイヤーが受けるダメージは、行動前にすべて盤面に表示される。
「知らないうちに死んでいた」を絶対に起こさない。

### 原則3. 操作の結果は実行前にプレビューする

押し出し・落下・連鎖・地形変化は、確定前に矢印と数値で表示する。
プレイヤーが予測できない挙動は、それ自体をバグとみなす。

### 原則4. やり直しのコストをゼロにする

Undoは無制限。リスタートは1操作。
「面倒だから適当に進める」状態を作らない。試行錯誤そのものが遊びの本体。

### 原則5. 1戦は短く、密度を高くする

2〜6ターンで決着。ダレる長期戦を作らない。
HPは1桁台に抑え、1回の判断ミスが即座に響くようにする。

## 3. 戦闘システム

### 3.1 盤面

| 項目 | 仕様 |
|------|------|
| グリッド | 6×6 を基本(ステージにより 5×5 〜 8×8) |
| 座標系 | 左上を `(0,0)`、右方向が `x+`、下方向が `y+` |
| 隣接 | 上下左右の4方向のみ(斜めは隣接扱いにしない) |
| 移動 | 4方向。移動力の分だけマスを消費して移動(斜め移動なし) |

**斜めを扱わない理由**: 射線・射程・押し出し方向の計算がすべて単純になり、
プレイヤーにとっても「見た目どおり」に動く。原則3を守るための選択。

### 3.2 タイル種別

| 種別 | ID | 移動 | 射線 | 効果 |
|------|----|------|------|------|
| 平地 | `plain` | 可 | 通す | なし |
| 壁 | `wall` | 不可 | **遮る** | 押し出したユニットが衝突する |
| 深穴 | `pit` | 不可 | 通す | 押し出しで落ちたユニットは**即死**(HP問わず) |
| 崩落床 | `crumble` | 可 | 通す | 指定ターン数経過後に `pit` へ変化。残りターン数を盤面に表示 |
| 高所 | `high` | 可 | 通す | このマスにいるユニットの射程 +1 |
| 隆起 | `rubble` | 可 | **遮る** | 移動コスト2。射線を遮る。攻撃を受けると `plain` へ |

深穴は本作で最も強力な戦術要素。**押し出して穴に落とせば、HPがいくつあろうと1手で排除できる。**
同時に自軍も落ちるため、穴の周囲は常に諸刃の剣として機能する。

### 3.3 ターン構造

1ターンは以下の順で進行する。

```
┌─ ターン開始
│   1. 地形処理      崩落床のカウントを1減らす。0になったら深穴化(上のユニットは落下)
│   2. 敵の移動      各敵が決定的AIに従って移動する
│   3. 敵の意図決定  各敵が攻撃対象「マス」を決定し、盤面にハイライト表示する
│
├─ プレイヤーフェイズ   ← ここでプレイヤーが考える。時間制限なし
│   4. 自軍ユニットを任意の順で1体ずつ行動させる
│      ・1ユニットにつき「移動」1回 +「アクション」1回(順序自由・片方のみも可)
│      ・行動済みでもターン終了前ならUndoで巻き戻せる
│   5. プレイヤーが「ターン終了」を選択
│
├─ 敵フェイズ
│   6. 敵が手順3で宣言した攻撃を実行する(宣言内容は変更されない)
│
└─ ターン終了
    7. 勝敗判定
```

#### なぜ「敵が移動してから予告」なのか

敵の移動を先に済ませることで、プレイヤーフェイズ開始時点では**敵は完全に静止しており、
盤面上の赤いハイライトがそのターンに起きることのすべて**になる(原則2)。

「次のターンに敵がどこへ動くか」は予告されないが、
敵AIは決定的でルールを公開しているため(3.7参照)、プレイヤーは推論できる。
**現在ターンの脅威は完全情報、次ターン以降は推論** — この線引きを本作の基本とする。

### 3.4 攻撃対象は「ユニット」ではなく「マス」

敵は「守衛を攻撃する」のではなく「マス `(2,3)` を攻撃する」と宣言する。

この一点が本作の戦術のすべてを生む。

- 対象マスから移動すれば、敵の攻撃は**空振りする**
- 対象マスへ別のユニット(敵を含む)を押し込めば、**敵の攻撃を敵に当てられる**
- 対象マスに壁を生成すれば、攻撃を無効化できる

「敵を倒す」より「敵の攻撃を無駄にする」ほうが基本的に効率がよいバランスにする。

### 3.5 ユニットの基本パラメータ

| パラメータ | 説明 | 想定範囲 |
|-----------|------|---------|
| `hp` / `max_hp` | 体力。0で戦闘不能 | 3〜8 |
| `move` | 1ターンに移動できるマス数 | 1〜4 |
| `actions` | スキルのリスト | 1〜3個 |
| `faction` | `player` / `enemy` | — |
| `weight` | 重量。`heavy` は押し出しの影響を受けない | `normal` / `heavy` |

HPを1桁に抑えることで、ダメージ計算を暗算可能にする。
プレイヤーが電卓なしで最善手を確認できることは、パズルとして必須の条件。

### 3.6 スキル(アクション)の定義

すべてのスキルは以下の要素の組み合わせで表現し、データファイルで定義する。

| 要素 | 説明 | 例 |
|------|------|-----|
| `range` | 射程。`{min, max}` | `{1,1}` = 隣接のみ、`{2,4}` = 2〜4マス |
| `shape` | 対象範囲 | `single` / `line`(直線貫通) / `cross`(十字) / `area1`(周囲1マス) |
| `needs_los` | 射線を必要とするか | 弓は `true`、投擲は `false` |
| `damage` | ダメージ量(固定値) | 0〜4 |
| `push` | 押し出しマス数と方向 | `{dir: "away", dist: 1}` |
| `effect` | 追加効果 | `create_wall` / `pull` / `swap` など |

#### 押し出しの解決順序

押し出しは本作で最も頻繁に起きる処理なので、順序を厳密に定める。

1. 押される方向の隣接マスを見る
2. **深穴** → 落下。**即死**。処理終了
3. **壁 / 隆起 / 盤外** → 移動できない。押されたユニットに**衝突ダメージ1**
4. **他のユニットがいる** → 移動できない。**押した側と押された側の双方に衝突ダメージ1**
   (※連鎖して押し出すことはしない。実装と予測を単純に保つため)
5. **空きマス** → 移動する。残り押し出し距離があれば1へ戻る
6. `weight: heavy` のユニットは押し出しを受けない(ダメージのみ通る)

### 3.7 敵AI(決定的アルゴリズム)

**敵は乱数を使わず、以下の優先順位で毎ターン必ず同じ判断をする。**
このルールはゲーム内のヘルプでプレイヤーに全文公開する。読めることが戦術になるため。

#### 移動の決定

```
1. 現在位置から攻撃可能な自軍ユニットがいる → 移動しない
2. いない → 最も近い自軍ユニットへ、最短経路で move の分だけ近づく
   ・最短経路が複数ある場合は「x座標の小さい方 → y座標の小さい方」を選ぶ(タイブレーク)
   ・深穴・壁は経路に含めない
   ・自分から見て安全かどうかは考慮しない(敵は自己保存をしない)
3. 到達できる自軍ユニットが1体もいない → 移動しない
```

#### 攻撃対象マスの決定

```
1. 攻撃範囲内の自軍ユニットを列挙する
2. 複数いる場合の優先順位
   a. 最もHPが低いユニット
   b. 同値なら、自分から近いユニット
   c. なお同値なら、x座標の小さい方 → y座標の小さい方
3. 範囲内に自軍がいない → そのターンは攻撃しない(意図を表示しない)
```

タイブレークまで明文化するのは、**プレイヤーが敵の行動を完全に予測できる**ことを
保証するため(原則1・2)。「なぜかこっちを狙われた」を発生させない。

### 3.8 勝利条件・敗北条件

勝利条件はステージごとに設定する。単調さを避けるため、殲滅戦のみにはしない。

| 種別 | ID | 内容 |
|------|----|------|
| 殲滅 | `annihilate` | 敵を全滅させる |
| 生存 | `survive` | 指定ターン数を耐える |
| 到達 | `reach` | 指定マスに自軍ユニットを到達させる |
| 護衛 | `protect` | 指定の中立ユニットを指定ターン数守り切る |
| 破壊 | `destroy` | 指定オブジェクトを破壊する |

敗北条件(共通):

- 自軍ユニットが**全滅**した
- 勝利条件が達成不可能になった(護衛対象の死亡など)

**自軍ユニットが1体倒れただけでは敗北にしない。** 倒れたユニットは次の戦闘で復帰する。
「1体犠牲にして勝つ」を戦術の選択肢として残すため。ただし後述のスコア評価では減点する。

### 3.9 Undo(巻き戻し)

| 操作 | 挙動 |
|------|------|
| Undo | 直前の1操作を取り消す。**回数無制限、ターンをまたいでも可** |
| Redo | Undoを取り消す |
| リスタート | ステージ開始時点に戻す。1操作で実行 |

**乱数がないため、Undoしても盤面は完全に同じ状態に戻る。**
「ロードして運を引き直す」不正が原理的に存在しないので、Undoを制限する理由がない。

これは実装に強い制約を課す(4.2参照)。ゲーム状態を完全にシリアライズできる設計を最初から採る。

### 3.10 スコア評価

各ステージにクリア後の評価を3項目設ける。やりこみ要素であり、クリア自体には不要。

| 項目 | 例 |
|------|-----|
| ターン数 | 3ターン以内にクリア |
| 無傷 | 自軍が1ダメージも受けずにクリア |
| ステージ固有 | 敵を1体も倒さずにクリア / 全ての敵を穴に落とす など |

固有条件は「別解を発見させる」ためのヒントとして機能させる。

## 4. ユニット・敵の初期定義

数値はプロトタイプ用の初期値。実装後の調整前提。

### 4.1 自軍ユニット(3クラス)

#### 守衛(Warden) — 前衛・押し出し役

| HP | 移動 | 重量 |
|----|------|------|
| 6 | 2 | heavy |

| スキル | 射程 | 範囲 | ダメージ | 効果 |
|--------|------|------|---------|------|
| 打ち払い | 1 | single | 2 | 対象を1マス押し出す |
| 踏み込み | 2 | single | 1 | 対象の手前まで移動してから攻撃 |

`heavy` により敵に押し返されない。壁役として盤面に居座り、敵を穴の方向へ押していく。

#### 弩弓兵(Arbalest) — 後衛・射線管理

| HP | 移動 | 重量 |
|----|------|------|
| 4 | 3 | normal |

| スキル | 射程 | 範囲 | ダメージ | 効果 |
|--------|------|------|---------|------|
| 狙撃 | 2〜4 | single | 3 | 射線が必要。射程1(隣接)には撃てない |
| 貫通射 | 2〜3 | line | 2 | 直線上の全ユニットに命中(**自軍にも当たる**) |

射程の下限があるため、敵に張り付かれると無力化される。位置取りが最も重要なクラス。

#### 術師(Artificer) — 盤面操作

| HP | 移動 | 重量 |
|----|------|------|
| 4 | 2 | normal |

| スキル | 射程 | 範囲 | ダメージ | 効果 |
|--------|------|------|---------|------|
| 障壁 | 1〜3 | single | 0 | 空きマスに壁を生成(3ターンで消滅)。**敵の攻撃予告を無効化できる** |
| 引き寄せ | 2〜4 | single | 0 | 対象を自分の方向へ1マス引き寄せる。射線が必要 |

ダメージを出さないが、敵を穴へ引き寄せる・攻撃予告のマスに壁を置くなど、
本作の「攻撃を空振りさせる」思想を最も体現するクラス。

### 4.2 敵ユニット(5種)

| 名称 | HP | 移動 | 重量 | 攻撃 | 特徴 |
|------|----|------|------|------|------|
| 徘徊者 | 3 | 2 | normal | 隣接1マス / ダメージ2 | 基本の敵。数で押す |
| 射手 | 2 | 2 | normal | 直線 射程2〜4 / ダメージ2 | 射線が通らなければ攻撃できない。壁で無力化可 |
| 突撃者 | 4 | 3 | heavy | 直線突進 / ダメージ3 + 押し出し1 | 押し返せない。誘導して壁に激突させる |
| 爆散体 | 2 | 1 | normal | 隣接1マス / ダメージ1 | **撃破時に周囲1マスへダメージ2**。敵の密集地で倒すと連鎖する |
| 増殖体 | 5 | 0 | heavy | なし | **2ターンごとに隣接マスへ徘徊者を1体生成**。放置すると盤面が破綻する |

#### 敵設計の意図

5種それぞれが**異なる問い**をプレイヤーに投げるよう設計する。

| 敵 | プレイヤーへの問い |
|----|------------------|
| 徘徊者 | 誰が最初に殴られるか、その位置でいいのか |
| 射手 | 射線をどう切るか |
| 突撃者 | 押せない敵をどう処理するか(誘導・地形利用) |
| 爆散体 | いつ・どこで倒すか(倒す順序そのものが戦術) |
| 増殖体 | 目の前の脅威と、放置すると詰む脅威のどちらを先に潰すか |

爆散体と増殖体は「敵を倒す＝常に正しい」という前提を崩すために置く。
爆散体は倒すタイミングが悪ければ自軍が巻き込まれ、増殖体は倒さなければ負ける。

## 5. メタ進行(塔の踏破)

### 5.1 構造

```
1階 ─┬─ 2階A ─┬─ 3階A ─┐
     │         │         ├─ 4階(ボス) ─ 5階 …
     └─ 2階B ─┴─ 3階B ─┘
```

- 全10〜15階層。5階ごとにボス戦
- 各階層で2〜3の分岐があり、通る戦闘を選べる
- 分岐には「難易度」と「報酬の種別」が表示される(選択に情報を与える)

**分岐もランダムではなく、階層ごとに固定の構造とする(原則1)。**
繰り返し遊ぶ動機は「ランダムだから毎回違う」ではなく
「別の攻略ルート・別解・スコア更新」で作る。

### 5.2 報酬

戦闘クリアごとに、提示された**3択から1つを選んで**獲得する。選択肢はステージごとに固定。

| 種別 | 例 |
|------|-----|
| 新スキル | 守衛が「2マス押し出し」を習得 |
| 強化 | 弩弓兵の射程 +1 |
| 装備 | 「重り」: 装備者が `heavy` になる |
| 回復 | 倒れたユニットの即時復帰、HPの全回復 |

3択のうち1つしか取れないことで、周回ごとに異なるビルドが成立する。

### 5.3 セーブ

- 階層の移動時にオートセーブ
- 戦闘中の中断セーブに対応(ターン単位の状態を丸ごと保存する。4.2の設計がそのまま使える)

## 6. 実装設計

### 6.1 アーキテクチャ方針

**ゲームロジックと描画を完全に分離する。**

```
core/            ← Godotのノードに依存しない純粋なGDScriptクラス
  board.gd          盤面(タイル配列)
  unit.gd           ユニット
  game_state.gd     盤面 + 全ユニット + ターン数。ゲームの状態はすべてここに集約する
  rules.gd          移動可能マス・射程・射線・押し出しの計算
  enemy_ai.gd       決定的AI(3.7の実装)
  action.gd         1操作を表すデータ。適用と巻き戻しができる

presentation/    ← 描画・入力。core を読むだけで、状態を直接書き換えない
  board_view.gd
  unit_view.gd
  preview_overlay.gd   移動範囲・攻撃範囲・押し出し矢印の表示

data/            ← JSON。コードを触らずに調整できるものはすべてここ
  units.json
  skills.json
  stages/01_01.json …
```

この分離により、**GUIなしでロジックの単体テストが書ける**。
乱数がないため、テストは「この盤面でこの操作をすればこの盤面になる」という
完全に決定的なアサーションとして書ける。仕様書がそのままテストケースになる。

### 6.2 Undoの実装方針

2案あるが、**案Bを採用する。**

| 案 | 方式 | 評価 |
|----|------|------|
| A | 操作の逆操作を実装して戻す | メモリ効率は良いが、押し出し連鎖や地形変化の逆操作が複雑でバグの温床になる |
| **B** | **操作前に `game_state` 全体のスナップショットを保存し、Undoは差し替えるだけ** | **実装が単純で確実。盤面は6×6・ユニット10体程度なので、スナップショットは数KB。何百手保存しても問題にならない** |

案Bの前提として、`game_state` は**完全にシリアライズ可能**でなければならない。
Godotのノード参照やシグナル接続を `game_state` に持ち込まないこと。
**これはプロジェクト開始時点で守るべき制約で、後から直すのは極めて困難。**

### 6.3 ステージデータ形式

```json
{
  "id": "01_01",
  "name": "最初の一手",
  "size": { "w": 6, "h": 6 },
  "tiles": [
    "......",
    "..##..",
    "..P...",
    "...oo.",
    "......",
    "......"
  ],
  "legend": { ".": "plain", "#": "wall", "o": "pit", "c": "crumble", "^": "high" },
  "player_units": [
    { "class": "warden",   "pos": [1, 4] },
    { "class": "arbalest", "pos": [0, 5] }
  ],
  "enemy_units": [
    { "type": "wanderer", "pos": [4, 1] },
    { "type": "archer",   "pos": [5, 0] }
  ],
  "victory": { "type": "annihilate" },
  "turn_limit": 6,
  "scoring": [
    { "id": "fast",   "type": "turns_within", "value": 3 },
    { "id": "flawless", "type": "no_damage" },
    { "id": "pitfall", "type": "custom", "desc": "全ての敵を深穴に落とす" }
  ]
}
```

タイルをASCIIアートで書けるようにすることで、**テキストエディタだけでステージを設計できる**。
専用のステージエディタを作る前でも、レベルデザインを進められる。

### 6.4 ステージ検証ツール(M3以降)

手作りステージの最大のリスクは「**解が存在しないステージを出荷してしまう**」こと。

乱数がないため、盤面の状態遷移は完全に決定的で、幅優先探索で解の存在を検証できる。
盤面6×6・自軍3体・6ターン以内という制約なら、
枝刈り(同一盤面の重複除去)を入れれば現実的な時間で探索できる見込み。

```bash
python3 tools/solve_stage.py data/stages/01_01.json
# → 解あり(最短4ターン / 解の総数 12通り)
```

「最短ターン数」が自動で分かるため、**スコア評価のターン数目標を機械的に決められる**という
副次的な利点もある。M3(ステージを量産し始める段階)までに用意する。

## 7. 画面仕様

### 7.1 画面遷移

```
タイトル → 塔マップ → 編成 → 戦闘 → リザルト → 塔マップ …
                                  └→ 敗北 → 塔マップ(その階から再挑戦)
```

### 7.2 戦闘画面のUI要素

| 要素 | 表示内容 |
|------|---------|
| 盤面 | タイル、ユニット、地形の残りターン数 |
| **敵の攻撃予告** | 対象マスを**赤くハイライト**。自軍がいるマスはさらに強調 |
| 移動範囲 | ユニット選択時、到達可能マスを青で表示 |
| 攻撃範囲 | スキル選択時、射程内を橙で表示。射線が通らないマスは暗く表示 |
| **結果プレビュー** | カーソルを合わせた時点で、ダメージ量・押し出し方向の矢印・落下の有無を表示 |
| ターン情報 | 現在ターン / 制限ターン、勝利条件 |
| **危険警告** | ターン終了時に自軍が被弾する場合、終了ボタンに警告を表示 |
| Undo / Redo / リスタート | 常時アクセス可能な位置に配置 |

**結果プレビューと危険警告は「あったら良い機能」ではなく、原則2・3を成立させる必須要件。**
これがない状態でプレイテストをしても、面白さの判断はできない。

### 7.3 アートの方針(暫定)

- 2Dドット絵 または シンプルな2Dイラスト
- **見やすさ優先**。盤面の状態が一瞬で読めることを、演出の派手さより優先する
- 素材はマイドライブ > ゲーム > 03_素材 で管理する
